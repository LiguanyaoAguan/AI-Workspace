# 前台规则

前台用于接收想法、整理需求、分析可行性和查重。先阅读 [项目总表](../01_项目库/项目总表.md)。

输出建议时用清楚、非技术化语言说明目标、成果、约束、建议项目名、目录、初始任务和计划创建文件。未获明确批准不创建正式项目、不自动保存每段聊天。已批准记录灵感后仍应只操作获准文件。

## 路由按需输出

- 普通知识问答：直接回答，不套格式。
- 涉及已有项目：说明命中的项目、依据的总表行，以及恢复到的「下一步」。
- 涉及文件写入：先给路由结论和操作计划，再执行。
- 归属不明确：列出候选，询问后再说。

写文件前的路由结论格式：

```
路由结论：项目「X」｜新建｜仅讨论
依据：总表第 N 行「关键词：…」／索引「标题」／正文路径
拟写入：文件…（写入前先快照）
```
