# 任务路由说明（第二阶段）

本文件是 [AGENTS.md](../AGENTS.md) 的细则。原则：**语义判断由 AI 完成，结构校验由脚本完成**。
脚本只回答"文件在不在、索引对不对、总表是否一致"，不判断"像不像、该不该"。

## 一、什么时候需要路由

| 你的输入 | 我的行为 |
| --- | --- |
| 普通知识问答 | 直接回答，不输出路由格式 |
| 提到某个项目、某件事的后续 | 先定位项目，再回答 |
| 要求写文件、改文件、入库 | 先给路由依据与计划，再执行 |
| 说不清属于什么 | 列候选问你，不猜 |

## 二、判断归属的顺序

1. **读项目总表**，按「项目名称 / 关键词·别名」与需求做语义比对。
2. **命中已有项目**：读该项目 `README.md`（定位、关键词）、`任务与进度.md`（权威待办与下一步）、`交接记录.md` 末尾，恢复上下文后再回应。
3. **未命中但相近**：说明相似点与差异，给出「并入现有项目 / 新建项目」两个选项及理由，等你选择。
4. **明确无关**：判断属于知识、技能、素材，还是仅需回答。
5. **仍不确定**：列候选并询问。

## 三、检索资料的方法

1. 先读 [知识索引](../02_知识库/索引.md)、[技能索引](../03_技能库/索引.md)。
2. 按「适用场景」做语义匹配，关键词只作辅助。
3. 命中候选后**必须打开正文确认**，不能只凭索引行作答。
4. 引用时注明路径与日期，例如：`02_知识库/命名约定.md`（2026-10-17）。

索引为空或没有相关条目时，如实说"未命中"，再给出替代方案，不假装存在。

## 四、避免重复创建

立项前至少做三项比对：

- 名称归一化后是否与已有项目相同或近似；
- 项目目标与已有项目是否重叠；
- 是否已有可复用的知识或技能条目。

有重叠时先提「并入」，并说明会保留哪些已有成果。脚本层面由 `新建项目.py` 拒绝同名目录、`检查工作区.py` 报告目录与总表不一致。

## 五、续作恢复

1. 总表行给出状态、关键词、下一步摘要（派生值）。
2. 读 `任务与进度.md` 确认权威待办与下一步。
3. 读 `交接记录.md` 末尾，确认已确认的决策与上次停点。
4. 复述："项目 X，上次做到…，下一步…，是否继续？"

## 六、写入前的路由结论

任何写入前输出：

```
路由结论：项目「X」｜新建｜仅讨论
依据：总表第 N 行「关键词：…」／索引「标题」／正文路径
拟写入：文件…（写入前先快照）
```

然后按「安全与回滚 2.0」执行：`begin`（写前快照）→ 编辑 → `end`（校验）→ `audit`；任一步失败即停。

## 七、示例

**B1 续作**：用户说"上次那个整理的事接着做"。
→ 读总表，命中「示例项目」（关键词：资料整理、归档）；读三件套；回复"下一步是整理第二批素材"；不新建项目。

**B2 相近但不新**：用户要"把资料整理成一套模板"。
→ 指出与「示例项目」目标重叠，给「并入 / 新建」两选项，等确认。

**B3 语义检索**：用户问"我上次说文件怎么起名来着"。
→ 索引中没有"起名"二字，但「适用场景」写着"新建资料时判断命名与落位"，命中并打开正文引用。

**B4 未命中**：用户要"做成 PPT"，技能库无相关条目。
→ 明确回复"技能库未命中"，给出可行替代，不编造技能。

**B5 入库**：用户给一段笔记。
→ 提出落位路径与索引行草案（标题／适用场景／主题词／摘要），批准后写入并登记，写前快照。

**B6 重复资料**：用户给的资料与已有条目内容重复。
→ 报重复并给「合并 / 新建版本」选项，不直接覆盖。

## 八、反例（不要这样做）

- 不看总表就说"这是新项目"。
- 只凭文件名相似就断定是同一件事。
- 索引为空时假装"库里有"。
- 每次对话都输出路由结论，哪怕只是普通问答。
- 在项目总表里手工改「下一步」，而不是改 `任务与进度.md` 后同步。

## 九、资料落位规则（02 / 03 / 04）

判定顺序：**先看是不是原始文件 → 再看能不能照着做 → 最后才看主题**。

| 资料形态 | 放哪里 | 判断标准 |
| --- | --- | --- |
| 原始文件：截图、录音、视频、PDF、原始草稿、未加工笔记 | `04_素材库`（或项目目录） | 未经提炼，作为来源保存 |
| 提炼后的结论、经验、要点 | `02_知识库` | 有适用场景、来源、验证状态，能被人复用 |
| 可调用流程、脚本、提示词、模板 | `03_技能库` | 有输入、步骤、输出、依赖，能照着做 |
| 只服务某个项目的资料 | 项目目录内 | 不复制到公共库；需要时把提炼版放 02 并注明来源项目 |

### 边界一：原始资料 vs 提炼知识

- 原件留在 `04_素材库` 或项目目录；**提炼结论另写一份到 02**，并在正文注明来源路径。
- 不在两个目录各存一份完整原文；要引用时写路径，不复制。

### 边界二：操作教程 vs 可调用技能

- **教程**解释"为什么、怎么做"，读完要靠自己组织步骤 → `02_知识库`。
- **技能**给出"输入 → 步骤 → 输出"，可直接照做，或含脚本/命令/模板 → `03_技能库`。
- 两者都有时：拆成两件（技能在 03，原理摘要指回 03 或 02），或先入 03 并在开头写一段原理摘要。

### 边界三：同一资料属于多个项目

- 物理位置**按资料类型**放，不按项目分目录。
- 在文件开头写 `相关项目：A、B`，索引摘要里注明；**不复制多份**。
- 项目文档需要引用时用相对路径指向公共库中的那一份。

### 边界四：什么时候必须向用户确认

1. 三个库都说得通（例如既有原始数据又有结论）。
2. 既是原件又要直接当结论用。
3. 需要移动或删除已有资料。
4. 需要写入公共库（02/03）而用户没有明确要求。
5. 关键词、归属或项目关联无法从现有信息判断。

无法判断时：先放 `00_前台/灵感箱` 并说明原因，**不直接进公共库**。

### 快速判定示例

| 输入 | 判定 |
| --- | --- |
| 一段会议录音 | 04_素材库（原始） |
| 从录音提炼的 5 条结论 | 02_知识库（提炼） |
| "如何写会议纪要"的步骤 + 模板 | 03_技能库（可调用） |
| 只给某项目用的脚本 | 项目目录；可复用再进 03 |
| 一份笔记前半是原文、后半是结论 | 拆开：原文 04，结论 02，互相引用 |
