# .ai-workspace 说明

本目录存放**系统级恢复数据**，不参与日常阅读，也不属于七大业务目录。

```
.ai-workspace/
├── backup/                 每次快照一个子目录
│   └── <编号>/
│       ├── manifest.json   清单：相对路径、大小、SHA256、原因
│       └── files/…         文件原样副本，保持原有目录结构
└── changes.log             只追加的变更日志，一行一条 JSON
```

## 快照编号规则

`YYYYMMDD-HHMMSS`，例如 `20261017-151230`。同一秒内多次快照时自动加序号
（`20261017-151230-2`、`-3`……），用“先创建目录再写入”的方式保证不会覆盖已有快照。

## 清单字段

| 字段 | 含义 |
| --- | --- |
| `schema` | 格式版本，当前为 1 |
| `id` | 快照编号，与目录名一致 |
| `created_at` | 创建时间（带时区） |
| `operation` | edit / overwrite / delete / move / pre-restore / auto-index / manual |
| `reason` | 快照原因，由操作者填写 |
| `source` | 调用方：`快照.py` 或 `新建项目.py` |
| `files[].path` | 工作区相对路径，不含设备路径 |
| `files[].sha256` | 备份副本的校验值 |

## 日志字段

`changes.log` 每行一条 JSON：`ts`、`id`、`action`、`status`、`operation`、`reason`、
`source`、`files`、`completed`、`failed`、`error`、`pre_snapshot`。

`status` 只有三种取值：`ok`（全部成功）、`partial`（部分完成，`completed` 记录实际完成的项）、
`failed`（完全未完成）。日志只追加，永不改写历史条目。

## 常用命令

```sh
python3 06_工具箱/快照.py snapshot --reason "修改说明" README.md
python3 06_工具箱/快照.py delete --reason "清理草稿" 04_素材库/草稿.md --confirm
python3 06_工具箱/快照.py restore 20261017-151230
python3 06_工具箱/快照.py restore 20261017-151230 --confirm
python3 06_工具箱/快照.py verify 20261017-151230
python3 06_工具箱/快照.py list
python3 06_工具箱/快照.py log --tail 20
```

## 边界与限制（必须知道）

1. **只保护点名的文件**，不做全量备份；没被点名的文件不在保护范围内。
2. 所有路径都相对工作区根目录，整个文件夹可整体迁移；不记录任何设备绝对路径。
3. 安卓文件管理器默认隐藏以点开头的目录，查看内容请用 `快照.py list`。
4. `AGENTS.md` 只是行为约定，不是系统级强制保护。**绕过快照工具直接修改文件，无法保证可自动回滚。**
5. 恢复前会先保存当前版本（`pre-restore` 快照），因此恢复本身也可撤销。
6. 快照会占用磁盘空间，用 `prune --keep N` 清理旧快照（默认只预览，需 `--confirm` 才删除）。
